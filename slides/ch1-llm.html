AI 学堂 · 第 1 讲

大模型基础

AI 为什么会一本正经地胡说八道
—— Token、训练、温度与幻觉

大模型在做什么：下一词预测

把大模型想象成一台超大规模的补全机器：给它一段文字，它预测下一个 token 是什么，然后把它接上去，再预测下一个，循环往复。

  • 输入「今天大盘三大指数集体」，它接「上涨」的概率最高
  • 输入「贵州茅台的主要产品是」，它接「白酒」
  • 它没有「查资料」的动作，每一步都是按语言概率生成
关键认知
聪明、流畅、博学，都建立在「预测下一个词」这一个动作上。这个本质决定了它擅长什么、也决定了它会在哪里出错。

Token：AI 眼中的文字

模型不直接读文字，文字先被切成 token（词元）。一个 token 可能是一个字、半个词、一个标点。

  • 英文约 0.75 个单词 / token，中文约 0.6 个汉字 / token
  • API 按 token 计费：输入、输出分开算钱
  • 模型能「记住」的对话长度上限，也叫上下文窗口，单位同样是 token
「股票」 → ["股", "票"]        2 个 token
"MACD golden cross" → ["MAC","D"," gold","en"," cross"]  5 个 token
估算：1 万字中文文档 ≈ 1.7 万 token
为什么要关心
成本核算、上下文塞不塞得下、被截断丢信息，全都发生在 token 这一层。

训练三阶段：从语料到助手

  • 预训练：读遍互联网规模的语料，学会语言与世界知识。贵（千万美元级），知识凝固在训练截止日
  • SFT 监督微调：用人工编写的高质量问答对，教会模型「以对话方式工作」
  • RLHF 人类反馈强化学习：人类对多个回答排序，模型学会「说得让人喜欢」
注意
RLHF 优化的是「讨人喜欢」，不是「更准确」。一个自信流畅的错误答案，比一个磕磕绊绊的正确答案更容易通过人类偏好这关——这是幻觉的温床之一。

对话的本质：拼接一段文字

你以为在「和一个人聊天」，实际上每次请求都是把系统提示 + 全部历史对话 + 新问题拼成一整段文字，发给一个没有记忆的补全机器。

  • 「它记得我」= 历史被重新拼进去（或做了记忆检索）
  • 上下文窗口有限，超长对话的最早内容会被截断
  • 换个会话/清空缓存，一切归零
对产品的意义
聊天记录是产品的数据资产，不是模型的能力。要做长期记忆，得自己设计存储与检索（第 3、4 讲展开）。

温度：创造性的旋钮

  • 温度低（接近 0）：总选概率最高的词。输出稳定、保守、可复现
  • 温度高（接近 1）：按概率抽样，低概率词也有机会。输出多样、有惊喜、也更不稳定
写行情摘要、抽取 JSON、分类打标  →  temperature = 0
写营销文案、起名字、闲聊      →  temperature = 0.7 ~ 1.0
股宇宙场景
一切要数字准确、格式稳定的功能（数据摘要、资讯打标、结构化抽取）一律低温度；创意生成才开高温度。

幻觉：不是 bug，是本性

幻觉（Hallucination）：模型生成了流畅、自信、但与现实不符的内容。

  • 它不是在「回忆数据库」，是在按概率补全——概率最高的那个词未必是真的那个
  • 训练数据里没有或过时的知识，它宁可编一个合理的，也倾向给出答案（RLHF 教它「要有帮助」，没教它「可以说不知道」）
  • 提问方式也会诱导：「给出 2024 年茅台净利润的具体数字」这种问法，等于命令它编

案例：问 AI 一个财务数字

实测常见结果
问：贵州茅台 2024 年净利润是多少？
答：约 862 亿元（数字看起来非常合理，带单位、带口径，甚至带同比）——但很可能是训练数据里某个年份的数字，或干脆是编的。
  • 数字格式完全正确 ≠ 数字本身正确，流畅度与真实性无关
  • 模型不知道自己「不知道」，它没有这条知识的可信度标记
  • 越具体、越小众的事实，幻觉风险越高（大众常识通常没问题）

股宇宙场景的幻觉清单

  • 行情数据：价格、涨跌幅、成交量——必须来自行情接口，永远不让 AI 生成
  • 财务数据：净利润、PE、ROE——同样走接口或已核对的数据库
  • 科普内容：K 线形态、指标含义这类稳定知识，幻觉风险低，可以放给 AI
  • 表述规范：AI 参与生成的内容要标注来源；关键数字上线前人工核对
一句话原则
事实靠系统，语言靠模型。数字与行情走确定性链路，AI 只负责组织语言，不负责生产事实。

缓解幻觉的四种武器（预告）

  • 提示词约束：明确允许它说「不知道」，禁止编造来源 → 第 2 讲
  • RAG 检索增强：先从股宇宙知识库检索原文，让 AI 只依据资料回答 → 第 3 讲
  • 工具调用：行情财务数据直接调接口拿真值，绕过生成 → 第 4 讲
  • 评测与红线：上线前用评测集量化幻觉率，合规红线前置 → 第 5 讲

没有一种手段能消灭幻觉，工程做法是层层设防：让错误概率低到业务可接受，且错了能被发现。

本讲小结

  • 大模型 = 按概率预测下一个 token 的补全机器，一切能力与缺陷源于此
  • token 是成本与上下文的计量单位；训练知识凝固在截止日
  • 对话是拼接文字，记忆是产品功能不是模型能力
  • 温度控制稳定性：业务功能用低温度
  • 幻觉是本性不是故障：事实靠系统，语言靠模型

练一练

1. 向 AI 提一个它不可能知道的小众数字，观察它如何「自信地编」
2. 同一个问题分别在温度 0 和 1 下各问 3 次，对比输出差异
3. 数一数：一篇 5000 字的研报摘要大约多少 token？成本多少？
