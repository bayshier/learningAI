AI 学堂 · 第 4 讲

Agent 与工具调用

让 AI 亲自查行情、操作界面
—— ReAct、工具定义与 MCP 实战

Agent：模型 + 工具 + 循环

普通 AI 调用是「一问一答」；Agent 是让模型自主拆解任务、调用工具、根据结果继续决策，循环往复直到完成。

  • 模型：负责思考与决策（大脑）
  • 工具：行情接口、数据库查询、UI 操作（手脚）
  • 循环：观察结果 → 决定下一步 → 再观察（神经系统）
为什么重要
第 1 讲的结论在这里兑现：事实靠系统。Agent 让模型从「生成答案」变成「调用系统拿真值再组织答案」，幻觉的根源被绕开。

ReAct：思考-行动-观察循环

用户：帮我看看茅台最近一个月走势，并对比大盘

思考：需要茅台日K数据 → 行动：get_kline("600519", "1D", 30)
观察：返回 30 根K线，累计 +6.2%
思考：还需要大盘数据 → 行动：get_kline("SH000001", "1D", 30)
观察：上证指数累计 +2.1%
思考：数据齐了 → 行动：生成对比总结（附数据来源）
  • 每一步都写明「为什么调、调什么、看到什么」，过程可审计
  • 循环上限（步数）由我们设定，防止无限打转

工具定义：描述就是说明书

{
  "name": "get_kline",
  "description": "获取股票日K线数据。返回开高低收与成交量。",
  "parameters": {
    "symbol":  {"type": "string", "description": "6位代码，如 600519"},
    "period":  {"type": "string", "enum": ["1D","1W","1M"]},
    "days":    {"type": "integer", "minimum": 1, "maximum": 250}
  }
}
  • 模型选工具、填参数全靠 description：描述含糊，调用必错
  • 用 enum、范围约束把参数空间锁死，幻觉参数在 schema 层就被拦截

MCP：工具的 USB 接口

MCP（Model Context Protocol）是 Anthropic 发起的开放协议，把「工具怎么被发现、描述、调用」标准化。

  • MCP Server：把能力（行情、数据库、App 控制）封装成标准工具集
  • MCP Client：Claude Code、Codex 等 AI 应用，自动发现并调用这些工具
  • 一次封装，处处可用：换模型、换客户端，工具层零改动
类比
MCP 之前每个 AI 应用与每个工具都要单独对接（N×M）；MCP 之后工具实现一次协议，所有客户端都能用（N+M）。

团队实战：kline-mcp

团队真实项目：把 K 线行情能力封装成 MCP Server，AI 客户端即可自主看盘。

  • 暴露工具：K 线查询、指标计算、形态识别输入
  • 数据来自行情源（真值），AI 只负责组织分析与表述
  • 自然语言 → 工具调用：「茅台最近一个月走得怎么样」自动翻译成 get_kline 调用
为什么它是对的
第 1 讲原则的完整落地：价格涨跌幅永远来自接口，AI 一个数字都不用编。

团队实战：android-mcp

另一个真实项目：把 Android 设备操作封装成 MCP 工具，AI 可以直接操控 App 界面。

  • 工具粒度：点击、输入、滑动、截图、读界面元素
  • 用途：自动化回归验证——「打开股宇宙，进入自选页，截图确认列表渲染正常」
  • 价值：把写 UI 自动化脚本变成说一句话，测试同学与 AI 的协作界面
边界意识
能操作 UI 就能误操作 UI。它跑在测试环境与受控设备上，不碰生产账户，这是下一页闸门设计的现实理由。

Agent 失控的三种模式

  • 死循环：同一工具反复调用、结果一直不满足，token 烧给空气
  • 错误级联：一步参数填错，后续全建立在错误结果上，还自我感觉良好
  • 越界行动：为了「完成任务」调用了不该调的工具（下单、发帖、删数据）
认知
Agent 的智能来自模型，Agent 的风险来自权限。能力越强，闸门越重要。

闸门设计：给 Agent 系上安全绳

  • 步数上限：循环超过 N 步强制停止，输出已完成的中间结论
  • 工具分级：只读工具（查询、截图）自动放行；写操作（下单、发送、删除）必须人工确认
  • 沙箱隔离：文件与网络访问限制在任务目录内，与团队 harness 的 fail-closed 沙箱实践一致
  • 全程留痕：每一步思考与调用记日志，出问题可回放定位

多 Agent 协作：主从模式

  • 主 Agent：理解需求、拆任务、分派、验收，唯一对用户负责
  • 子 Agent：领一个边界清晰的任务，任务描述里写明范围与验收标准
  • 验收权在主 Agent：子 Agent 的产出是提案不是结论，核验后才采信
团队实践参考
harness-engineering 项目的多 Agent 协同（OODA 循环、自进化 Skill）就是这套模式的工程化样本，博客有完整拆解。

本讲小结

  • Agent = 模型 + 工具 + 循环：让 AI 调系统拿真值，绕开幻觉根源
  • 工具描述就是说明书，参数空间用 schema 锁死
  • MCP 让工具一次封装处处可用：kline-mcp、android-mcp 是团队现成样本
  • 失控防护三件套：步数上限、工具分级、沙箱留痕
  • 多 Agent 主从协作：分派 + 验收，产出是提案不是结论
